# 프런트엔드 디자인

활성 레포(`.fullops-squad/fullops.toml`이 있는 레포)에서 UI를 바꾸는 작업에만 쓴다. 표식이 없으면 `setup-fullops`를 안내한다. UI 변경이 없는 작업에는 이 절차를 적용하지 않는다.

명령 표기: 이 문서의 `fullops`는 Claude Code 세션에서 그대로 실행된다. Codex·grok·agy 세션에서는 고정 위치 실행본을 전체 경로로 부른다: `~/.fullops/bin/fullops`(Windows는 `%USERPROFILE%\.fullops\bin\fullops.exe`).

## 1. 범위와 선택

`fullops.toml`, `.fullops-squad/project.md`, 공통 코딩 규칙, 현재 역할 인박스를 읽는다. 이번 과제의 선택은 역할 인박스가 정본이다.

호스트·모델·effort는 대화의 사용자 지정, 이번 과제에 기록된 값, `orca-agents.md`의 모델 후보 순으로 따른다. 호스트를 바꾸면 이전 제공사의 모델 이름을 그대로 넘기지 않는다. 브랜드별 우열을 전제로 자동 배정하지 않는다.

주 스킬은 하나만 고른다. 사용자가 지정한 스킬이 먼저다.

| 작업 | 주 스킬 | 필요할 때의 보조 검토 |
|---|---|---|
| 새 화면, 시각 방향, 화면 구현 | `frontend-design` | 코드 접근성 검토에 `web-design-guidelines` |
| 팔레트·폰트·스타일·디자인 시스템 검색 | `ui-ux-pro-max` | 기존 화면과의 일관성 검토 |
| 기존 화면의 비평·audit·polish | `impeccable` | 코드 검토에 `web-design-guidelines` |

네 스킬은 `fullops install`이 네 호스트에 사용자 스킬로 설치한다. 설치됐는지는 `fullops install --check`가 알려 준다(빠진 것은 `<호스트>: skill <이름>` 줄로 나온다). 주 스킬과 이번 보조 검토의 원문만 읽는다.

선택형 도구(브라우저 조작 도구, Impeccable 엔진, shadcn 연동)는 플러그인이 설치하지 않는다. `fullops install --check`와 `fullops doctor`가 안내만 하고, 쓰는 레포가 직접 설치한다. 설치돼 있지 않으면 그 도구에 기대는 검사는 미실행으로 적는다.

완료 조건: 대상 화면과 범위, 호스트·모델·effort, 주 스킬과 보조 검토를 인박스에 적었다.

## 2. 디자인 정본과 인계

- 기존 `DESIGN.md`나 `project.md`가 가리키는 문서를 디자인 정본으로 쓴다. 기존 토큰과 공용 컴포넌트의 경로를 인박스에 연결하고 본문을 복제하지 않는다.
- 정본이 없으면 기존 화면·CSS·컴포넌트와 사용자 요구에서 방향을 정한 뒤 한 경로만 정본으로 지정한다. 새 정본을 만드는 것이 기존 디자인을 바꾼다는 뜻은 아니다.
- 지시서에는 대상 화면과 상태(빈 상태, 오류, 로딩 포함), 디자인 정본과 토큰·컴포넌트 경로, 피할 스타일의 구체적 목록, 수락 기준과 검증 방법을 적는다. 모호한 금지는 쓰지 않는다.
- 외부 스킬이 새 역할, 하위 에이전트, hook, 유료 서비스, 외부 업로드를 요구하면 FullOps의 권한과 병렬 방침(`.fullops-squad/rules/delegation.md`) 안에서만 따른다. 외부 스킬이 자기 hook을 자동으로 넣게 두지 않는다.

## 3. 구현·비평·검증

- 구현은 `fullops-work`의 작업과 완료 순서를 따른다. 토큰과 공용 컴포넌트를 먼저 쓰고 정본에 없는 값을 새로 만들면 근거를 완료 보고에 적는다.
- 비평과 다듬기는 주 스킬의 절차대로 하고 결과를 인박스에 반영한다. 되돌릴 수 있는 디자인·문구·배치 선택은 묻지 않고 추천안으로 정한다.
- 검증은 `fullops-test`의 범위와 증거 규칙을 따른다. 레벨이 요구하지 않는 폭·테마의 캡처를 더하지 않는다. 디자인 lint 규칙이 레포에 있으면 `fullops lint`가 함께 돌린다.

## 4. 완료

완료 보고에 바꾼 화면, 따른 디자인 정본, 정본과 달라진 판단과 되돌리는 방법, 실행한 검증과 못 한 검증을 적고 `fullops done`으로 끝낸다. 디자인 정본을 바꿨으면 `fullops-deliverables`로 해당 산출물 문서를 갱신한다.
