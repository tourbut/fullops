# 작업 입력, 검수, 인계

활성 레포(`.fullops-squad/fullops.toml`이 있다)에서는 현재 역할 인박스의 기존 절에 아래를 채우거나 원천 문서를 연결한다. 별도의 중복 지시서를 만들지 않는다. 활성 레포가 아니면 `videos/<작업>/` 안에 같은 내용을 `scenes.md`와 `qa/`로 남긴다.

## 작업 입력

- 템플릿: 번호, 이름, 제작자, 원본 게시물 링크(또는 "템플릿 없이"), 고른 사람
- 목적, 시청자, 핵심 메시지, 사용처
- 길이, 폭·높이, FPS, 화면 비율, 루프 여부, 출력 형식
- 장면표: 시작·끝, 화면 내용, 전환, 실제 문구, 음성 시작·끝
- 브랜드: 색, 로고, 금지 요소, 참조 자료의 역할
- 음성: 없음 / 사용자 음원 / 코드 합성, 음량과 편집 조건
- 자산의 실제 경로, 출처, 라이선스, 필요한 글꼴과 글리프
- 허용 범위: 도구 설치, 외부 사이트 조회, 로컬 렌더

## 기술 검사

시간은 초, 구간은 시작 포함·끝 제외로 적는다. 계획한 문구 목록을 실제 렌더 화면과 대조한다.

```bash
ffprobe -v error -count_frames -show_streams -show_format -of json renders/v01/clip.mp4
ffmpeg -i renders/v01/clip.mp4 -vf "select='eq(n,0)'" -frames:v 1 qa/v01/first.png
ffmpeg -sseof -0.05 -i renders/v01/clip.mp4 -frames:v 1 -update 1 qa/v01/last.png
ffmpeg -i renders/v01/clip.mp4 -map 0:a:0 -acodec pcm_s16le qa/v01/final-audio.wav
```

길이, 폭·높이, FPS, 프레임 수, 스트림 종류를 장면표의 기대 값과 대조한다. 빠진 정보를 추정하지 않는다. 검사 도구가 없거나 입력이 잘못됐으면 `unavailable`, 규격이 다르면 `failed`다.

## 검수 기록

각 항목에 `passed`·`failed`·`not_run`·`unknown` 가운데 하나와 이유를 적는다.

| 검사 | 필요한 근거 |
|---|---|
| 실행·규격 | 실행한 명령, 종료 코드, 걸린 시간, 도구·OS, 실제 ffprobe 결과(길이, 크기, FPS, 프레임 수, 영상·음성 스트림) |
| 시각 | 첫 프레임, 장면 대표, 전환 직전·직후, 마지막 프레임의 파일 경로와 판정. 루프 작품은 첫·끝 프레임 비교 |
| 타이포·내용 | 한글 글리프, 글자 잘림·겹침·크기, 정확한 제품명·로고, 템플릿의 "금지" 위반 여부 |
| 음성 기술 | 음원 길이, 큐 시각, 끝 잘림, 출력의 peak·clipping·무음 |
| 청취 | 실제 최종 영상을 들은 사람과 판정. 듣지 않았으면 `not_run` |
| 권리 | 템플릿 출처 표기, 자산·글꼴·음원·도구의 라이선스 |
| 재렌더 | 인계한 소스·자산·명령만으로 다른 폴더에서 다시 렌더해 규격과 프레임을 비교했는지 |

- 파일이 있다는 것만으로 검수하지 않는다. 뽑은 프레임을 직접 본다.
- 종료 코드 0은 연출 수락이 아니다. 자동 검사는 문구의 정확성, 자연스러운 소리, 미적 완성도를 입증하지 못한다.
- 다시 렌더한 MP4가 바이트까지 같다고 보증하지 않는다.

활성 레포에서는 기록을 `.fullops-squad/docs/evaluations/qa-reports/<과제 키>-test/report.md`에 둔다(`fullops-test` 스킬). 재작업도 새 폴더를 만들지 않고 같은 `report.md`에 절을 덧붙인다. 그 폴더에 커밋하는 스틸·영상은 `report.md`가 상대 경로로 링크해야 한다. 큰 MP4는 커밋을 강제하지 않고 보관 위치를 적는다.

## 인계 완료

- 쓴 템플릿의 번호·이름·제작자·원본 링크와 고른 이유
- 최종 영상의 버전·경로, 수정할 수 있는 `index.html`, 다시 렌더하는 명령
- 음원·자산·글꼴 파일 또는 보관 위치, 출처와 라이선스
- 장면표와 큐 시각
- lock 파일, 실제 Node·브라우저·FFmpeg 버전
- 대표 프레임, 검수 결과, 확인하지 못한 항목
- 이전 버전과 실패한 렌더의 보존 위치, 다음 담당과 재개 조건

worker의 완료와 사용자의 최종 수락은 별개다. 수정 요청은 같은 과제의 새 출력 버전(`v02`)으로 반영하고 이전 성공 파일을 지우지 않는다. 활성 레포의 worker는 `fullops done`으로 끝낸다(`fullops-work` 스킬).
