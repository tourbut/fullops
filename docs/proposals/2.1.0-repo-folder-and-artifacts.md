# 2.1.0 명세: 레포 폴더 `.fullops/`, 문서 트리 재구성, 패킷 제거 (2026-11-17)

- 상태: 확정(레포 주인 결정 2026-11-17). 구현 뒤 `docs/design.md`(6.1절, 13절, 17절 H2)와 `docs/design-changes.md`에 반영한다.
- 결정: (1) 레포 폴더를 `.fullops/`로 바꾼다(결정 H2를 뒤집는다). (2) 패킷 기능을 통째로 뗀다. (3) 문서 트리를 체계적으로 다시 짠다.
- 근거: jevpet 점검(2026-11-17). `.fullops-squad/` 아래 커밋 파일 9,309개, `docs/evaluations` 약 850MB(탐색·패킷 파일 522MB, QA 이미지 191MB). 1.24.0 기계 파일과 사람 문서가 `docs/evaluations/` 한 곳에 섞여 있다. 과제 하나의 기록이 `handovers/logs/`, `routes/`, `reviews/`, `docs/evaluations/qa-reports/`, `docs/evaluations/jev/` 다섯 곳에 흩어져 있다.
- H2를 유지한 이유(Python판과 같은 폴더로 공존)는 Python판 플러그인을 Claude Code·grok에서 지우면서(2026-11-17) 사라졌다.

## 1. 원칙

1. **누가 쓰고 얼마나 사는가로 나눈다.** 설정(사람이 고치고 기계가 읽는다), 안내(사람이 고치고 에이전트가 읽는다), 진행(지금 과제), 기록(끝난 과제, 쌓인다), 산출물(제품 문서), 보관(옛 판 기록)이 각자 한 폴더다.
2. **과제 하나의 기록은 한 폴더에 모은다**: `tasks/<KEY>/`.
3. **사람이 읽거나 다른 워크트리가 커밋에서 읽어야 하는 것만 커밋한다.** 기계 중간 결과는 `<git-common-dir>/fullops/`에 둔다(모든 워크트리가 함께 보고 커밋되지 않는다).
4. 레포 상대 경로는 코드 한 곳(`fullops_core::layout`)에서만 만든다.

## 3. 경로 모듈 `fullops_core::layout`

- `pub const DIR: &str = ".fullops";`, `pub const LEGACY_DIR: &str = ".fullops-squad";`
- 레포 상대 경로(슬래시 표기)를 돌려주는 함수만 둔다: `config_toml()`, `plans()`, `lint_json()`, `review_json()`, `inbox(role)`, `inbox_dir()`, `task_dir(key)`, `route(key)`, `request(key)`, `handover_log(key, role, round)`, `review_dir(key, head12)`, `qa_dir(key)`, `deliverables_index()`, `guide(name)`, `template(name)`, `archive_dir()`.
- 흐름 기록 판정 하나: `pub fn is_record(path) -> bool` = `PLANS.md`, `inbox/`, `tasks/` 아래. 지금 `derive.rs`·`done.rs`·`hold.rs`·`packet.rs`·`review.rs`가 따로 가진 목록(`handovers/`, `docs/evaluations/`, `routes/`, `reviews/`, `PLANS.md`)을 이것으로 바꾼다.
- `fullops-store::Repo`의 경로 메서드는 `root.join(layout::…)`만 한다. 다른 곳에서 `".fullops"` 문자열을 만들지 않는다(시험·시나리오 제외).

## 4. 옛 자리 레포

- `discover`는 `.fullops/fullops.toml`만 활성 표식으로 본다. `.fullops-squad/fullops.toml`만 있는 레포는 비활성으로 본다(hook이 막지 않는다).
- 그런 레포에서 hook의 SessionStart와 `fullops` 명령(`migrate`, `doctor`, `status`, `install`, `upgrade` 제외)은 "이 레포는 옛 자리(`.fullops-squad/`)다. `fullops migrate --layout`으로 옮긴다"를 내고 명령은 종료 코드 2로 멈춘다. 이 판정은 `layout::legacy_marker(root)` 하나가 한다.
- 이유: 두 자리를 함께 읽게 하면 hook 규칙·lint·리뷰 범위가 모두 두 벌이 된다. 이전은 명령 하나라 유예를 두지 않는다.

## 5. `fullops migrate --layout [--dry-run]`

기준 브랜치(`[git].base`)를 체크아웃한 lead 체크아웃에서만 받는다. 한 커밋 `fullops: .fullops 자리로 옮김`을 만든다. 다른 워크트리는 `fullops sync`나 다음 `merge`의 동기화로 따라온다.

1. 거절: 작업 트리가 깨끗하지 않다, 열린 dispatch·보류가 있다, 인박스에 진행 중 과제가 있다, `.fullops/`가 이미 있다, 레포 루트가 사용자 홈이다(`~/.fullops/`와 겹친다), `.fullops-squad`가 심볼릭 링크다.
2. 2.1절 표대로 `git mv`한다(추적 파일). 추적되지 않은 `.env*`·`local/`은 파일 시스템에서 옮긴다. 대상이 이미 있으면 거절한다.
3. 지울 것(`docs/evaluations/jev/**`, `*-review/`의 OCR 중간 파일, 무시 목록에 있으면서 추적되는 파일)은 `git rm --cached`(작업 트리의 파일은 `.fullops/local/legacy/`로 옮긴다).
4. 커밋되는 글 안의 경로를 고친다. 대상: `.fullops/` 아래의 `guide/**`, `templates/**`, `config/*.json`, `PLANS.md`, `docs/deliverables/README.md`, 레포 루트의 `CLAUDE.md`·`AGENTS.md`·`GEMINI.md`의 fullops 관리 블록. 바꾸는 것: `.fullops-squad/<옛 경로>` → `.fullops/<새 경로>`(2.1절 표의 긴 접두어부터), 그 밖의 `.fullops-squad/` → `.fullops/`. `tasks/`·`archive/`의 기록은 고치지 않는다.
5. `config/review.json`의 exclude에 `.fullops/tasks/**`, `.fullops/archive/**`가 없으면 더한다. `.gitignore`를 새 템플릿 줄에 맞춘다.
6. `fullops.toml`의 `applied_version`을 실행본 버전으로 올린다.
7. `--dry-run`은 옮길 경로 수·지울 경로 수·고칠 파일 목록만 낸다.

`migrate --from-python`은 지금 순서대로 옮긴 뒤 같은 실행에서 이 단계를 이어서 해 곧바로 새 자리로 만든다. `init`은 새 자리로 만든다.

## 6. 패킷 제거

`fullops packet`, `check_packet`(D-12·R-10·리뷰 check 10번), `Packet`·`PacketOutcomes`, `Route.requires_packet`, dispatch spec의 `packet` 줄을 뗀다. `find`·`context`는 남기고 결과를 공용 디렉터리에 쓴다. 옛 route 기록의 `requires_packet` 키는 읽을 때 무시한다.
