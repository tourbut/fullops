# fullops 2.2.0

역할마다 쓸 수 있는 모델 후보를 `fullops.toml`의 `[models]`에 두는 판이다. 2.1.x까지는 `orca-agents.md`의 `## 모델 후보` 절에 두고 기계가 읽지 않았다.

## 달라진 것

- `fullops.toml`에 `[models]`를 둔다. 키는 등록 역할이거나 병합 전 리뷰 세션의 `reviewer`이고, 후보마다 `agent`(Orca 에이전트 ID: `claude`·`codex`·`grok`·`antigravity`), `model`, `effort`, `about`(어떤 작업에 쓰는지)을 적는다. 약하고 싼 후보부터 적는다.
- `fullops dispatch`에서 모델을 주지 않았고 route 기록도 없을 때, 그 자리의 후보가 하나면 그 후보를 쓴다. 여럿이면 거절(D-09) 문구에 후보를 보여 준다.
- 후보가 있는 자리에 목록 밖 조합을 주면 `--why "<근거>"`가 있어야 받는다(`route`는 RT-06, `dispatch`는 D-14). 사용자가 정한 조합은 근거와 함께 기록에 남는다. 후보가 없는 역할은 전과 같다.
- `orca-agents.md` 템플릿을 뗐다. 역할·책임은 `[roles]`, 모델 후보는 `[models]`, 배정 규칙(분류 기준, 모델 고르는 법, 중복 기동 금지)은 `fullops-orca` 스킬에 있다. 새 레포의 `fullops init`은 이 파일을 만들지 않는다.
- `fullops migrate --models [--dry-run]`을 더했다. `guide/orca-agents.md`의 후보 줄을 `[models]`로 옮기고(`agy`는 `antigravity`로), 옮긴 줄만 뺀다. 옮기지 못한 후보 줄과 후보 절 안의 사람 글은 `## 옮기지 못한 모델 후보 글` 아래에 남긴다. 그 뒤 파일 전체가 옛 기본 글 그대로면(배정표와 라우팅 줄까지) 지우고, 아니면 남긴 채 커밋 하나를 만든다. lead 체크아웃에서만 하고, 다시 실행해도 된다. `migrate --from-python`도 1.24.0의 후보를 같은 방법으로 옮긴다.
- `fullops upgrade`의 필수 적용에 `models`를 더했다(`orca-agents.md`에 `## 모델 후보` 절이 남아 있으면 걸린다).

## 적용

1. `npx --yes github:tourbut/fullops install`을 실행한다.
2. 레포마다 lead 체크아웃에서 `fullops migrate --models --dry-run`으로 옮길 후보와 `orca-agents.md`를 지울지 남길지 본다. 옮기지 않을 줄(등록되지 않은 역할, 모르는 agent, 형식이 다른 줄)이 나오면 고칠지 정한다.
3. `fullops migrate --models`를 실행하고 커밋을 확인한 뒤 push한다.
4. `orca-agents.md`가 남았으면 남은 글(레포 전용 운영 규칙)을 읽고, 지금 판에 맞지 않는 옛 이름을 고치거나 다른 문서로 옮길지 정한다. 도구는 이 글을 옮기지 않는다.
5. `fullops upgrade --verify`로 `applied_version`을 2.2.0으로 올리고 커밋한다.
