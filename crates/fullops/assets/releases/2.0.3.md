# fullops 2.0.3

Orca 1.4.261에서 배정이 되지 않던 문제를 고친 판이다.

## 달라진 것

- `fullops dispatch`가 Orca에 넘기는 요청 ID(`worker-start --retry-request`)를 UUID v4 꼴로 만든다. Orca 1.4.261은 UUID가 아닌 요청 ID를 `invalid_argument`로 거절한다. 2.0.2까지는 `req_`로 시작하는 ID를 써서, 이 Orca에서는 모든 배정이 "Orca가 배정을 거절했다"로 끝났다(종료 코드 4). 준비 커밋은 만들어지지만 worker는 뜨지 않았다.

## 적용

1. `npx --yes github:tourbut/fullops install`을 실행한다.
2. 2.0.2에서 거절된 배정은 같은 명령(`fullops dispatch <KEY> --role <역할>`)을 다시 실행하면 된다. 거절된 요청은 상태에 예약을 남기지 않는다.
