# fullops 2.1.0

레포 폴더를 `.fullops/`로 옮기고 그 안을 과제 단위로 다시 짠 판이다. 탐색 패킷 기능은 뗐다.

## 달라진 것

- 레포 폴더가 `.fullops-squad/`에서 `.fullops/`로 바뀌었다. 안은 설정(`config/`), 안내(`guide/`), 템플릿(`templates/`), 인박스(`inbox/to_<역할>.md`), 과제(`tasks/<KEY>/`), 산출물(`docs/`), 보관(`archive/`), 커밋하지 않는 작업 폴더(`local/`)로 나뉜다.
- 과제 하나의 기록이 `tasks/<KEY>/` 한 곳에 모인다: 분류 기록(`route.json`), 요청(`request.md`), 차수별 지시서와 완료 보고(`<역할>.r<n>.md`), 리뷰(`reviews/<head12>/`), QA 증거(`qa/`). 전에는 `handovers/logs/`, `routes/`, `reviews/`, `docs/evaluations/qa-reports/`에 흩어져 있었다.
- 탐색 패킷(`fullops packet`, 배정·완료·리뷰의 패킷 검사, 분류 기록의 `requires_packet`)을 뗐다. `find`·`context` 결과는 커밋되지 않는 Git 공용 디렉터리의 `fullops/explore/`에 쌓인다. 옛 분류 기록에 `requires_packet`이 남아 있어도 그대로 읽힌다.
- 옛 자리(`.fullops-squad/fullops.toml`) 레포는 활성 레포로 보지 않는다. 세션 시작에 안내 한 줄을 내고, 명령은 `FullOps[layout]`으로 거절하며 `fullops migrate --layout`을 안내한다.
- 새 명령 `fullops migrate --layout [--dry-run]`: 옛 자리를 새 자리로 옮기고 커밋 하나를 만든다. 탐색·패킷 파일과 무시 목록에 있으면서 추적되던 파일은 추적에서 빼고 작업 트리의 `.fullops/local/legacy/`에 둔다. 안내 문서와 설정의 경로, 엔트리 문서의 관리 블록을 고친다. push하지 않는다. `migrate --from-python`도 전환 끝에 이 자리 옮김을 함께 한다.
- lint: 새 규칙 `QA-001`(ERROR. `tasks/*/qa/`의 `raw/` 밖에 zip·영상·trace)과 `QA-002`(WARNING. 한 `qa/` 폴더의 이미지가 12장을 넘거나 한 장이 1MB를 넘는다). DOC-002·003은 `archive/`와 `tasks/*/reviews/`를 보지 않는다.
- `fullops doctor`: 무시 목록에 있으면서 추적되는 파일과 옛 자리 레포를 알린다.
- Orca 패널(2.1.0)이 `.fullops/fullops.toml`로 활성 레포를 찾는다.

## 적용

1. `npx --yes github:tourbut/fullops install`을 실행한다.
2. 레포마다 진행 중 과제(인박스, 열린 dispatch, 보류)를 끝내고, 기준 브랜치를 체크아웃한 lead 체크아웃에서 `fullops migrate --layout --dry-run`으로 계획을 본 뒤 `fullops migrate --layout`을 실행한다. 만들어진 커밋을 확인하고 push한다.
3. 역할 워크트리는 lead 체크아웃에서 `fullops sync`로 따라온다(2.1.1부터. 2.1.0 바이너리로 옮겼으면 `fullops sync --role <역할>`을 역할마다 실행한다). 2.1.1의 동기화는 워크트리에 남은 `.fullops-squad/`를 `.fullops/local/legacy/`로 옮기고 `.env` 링크를 다시 건다.
4. 안내 문서(`guide/**`)에 접두어 없이 적힌 옛 경로(`handovers/_TEMPLATE.md`, `lint/lint.json` 등)는 자동으로 고치지 않는다. 손으로 고친다.
5. 되돌리기는 자리 옮김 커밋의 `git revert`다. 추적되지 않던 `.env*`·`local/`은 `.fullops/`에서 손으로 되돌린다.
6. Orca 패널은 카탈로그에서 2.1.0으로 올린다.
